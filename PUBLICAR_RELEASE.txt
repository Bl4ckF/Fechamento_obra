PUBLICAR ATUALIZAÇÕES PEQUENAS — v1.3.3

O repositório mantém o projeto completo. Envie somente os arquivos modificados:
o próprio Git transmite as diferenças. Não apague os demais arquivos da pasta.

1. Aplique os arquivos desta atualização à pasta atual do seu repositório.
   app.py, version.json e web/index.html devem indicar 1.3.3.
2. Confira as alterações antes de enviar:
   git status
   git diff --stat
   git add app.py version.json web/app.js web/book.js web/learning.js web/index.html web/input-tools.css tools/criar_atualizacao.py tests/test_labor_editor_actions.js PUBLICAR_RELEASE.txt ATUALIZAR.txt
   git commit -m "v1.3.3: limpar alterações e remover mão de obra"
   git push origin main
   Troque main pela branch do programa, se ela tiver outro nome.
3. Crie e envie a tag no commit correto:
   git tag -a v1.3.3 -m "Fechamento de Obras v1.3.3"
   git push origin v1.3.3
4. No GitHub, abra Releases > Draft a new release, selecione v1.3.3 e
   anexe SOMENTE Fechamento_Obras_Engelmig_Atualizacao_v1_3_3.zip.
   Publique como Latest, sem marcar Pre-release. Não basta criar a tag:
   sem esse anexo, o atualizador baixa o código completo da tag.
5. Nos computadores com a base 1.3.2 instalada, use Configurações >
   Verificar atualização > Instalar atualização. O programa baixa o
   pacote anexado, substitui seus arquivos e reinicia automaticamente.
   A sincronização de registros é independente dessa atualização.

PRÓXIMAS VERSÕES
Mantenha o ZIP completo da versão 1.3.2 como referência fixa. Depois de
alterar a versão e o código, gere um pacote cumulativo a partir dessa base:

python tools/criar_atualizacao.py --base "C:\Backups\Fechamento_Obras_Engelmig_v1_3_2.zip" --saida "C:\Atualizacoes\Fechamento_Obras_Engelmig_Atualizacao_v1_3_4.zip"

O pacote reúne as diferenças desde a base, para que uma máquina ainda na
1.3.2 possa pular diretamente à versão nova. Não use o ZIP incremental como
base. app.py, updates.py, INICIAR.bat e version.json acompanham o pacote
porque são exigidos pelo atualizador já instalado. ATUALIZACAO.json lista
as versões e os hashes dos arquivos; é um inventário para conferência.
Exclusões de arquivos exigem tratamento próprio: o gerador bloqueia esse
caso porque o instalador atual só acrescenta ou substitui arquivos.

REQUISITOS
O aplicativo e o repositório precisam estar acessíveis conforme a configuração
existente; a instalação automática é para Windows e repositório público.
dados/, .git/ e runtime/ são preservados. Instalações anteriores à 1.3.2
precisam primeiro receber a base completa 1.3.2. O ZIP incremental não é
uma primeira instalação. Este pacote não publica a Release por conta própria.
